    Why Arrays Are Faster Than Linked Lists (It Starts with the CPU Cache!)

    2 minute read

    Published: May 09, 2026

    Most of us learn the classic computer science rule:

    Array access → O(1) Linked list access → O(n)

    But in real-world systems, Big-O notation doesn’t tell the whole story.

    Performance is often dominated by something entirely different: the CPU cache. 🧠

    Here is why your algorithm’s speed is dictated by hardware, not just math. 👇

    1. The Bottleneck: RAM vs. CPU Cache

    Modern CPUs are blazingly quick, but RAM is relatively slow. To avoid sitting idle waiting for RAM to deliver data, the CPU uses built-in cache memory:

    • L1 Cache → extremely fast, but very small
    • L2 Cache → medium speed and size
    • L3 Cache → larger, but slower

    The Key Idea

    The CPU doesn’t load memory byte-by-byte. It loads a “cache line” (usually a 64-byte block). If you ask for one value, the CPU grabs that value plus several neighboring values and pulls them all into the ultra-fast cache.

    2. The Array Advantage: Spatial Locality

    This is where arrays shine. Arrays are stored in continuous memory.

    Index:  0    1    2    3    4
Array: [10] [20] [30] [40] [50]

    When the CPU reads array[0], it doesn’t just get 10. It loads a whole cache line into L1: [10][20][30][40].

    When your loop moves to array[1], the CPU doesn’t have to talk to the slow RAM at all. The data is already in the cache! This results in an extremely fast traversal known as “spatial locality.”

    3. The Linked List Problem: Cache Misses

    Linked list nodes are allocated dynamically, meaning they are stored randomly across your RAM.

    A → D → B → F → C

    What happens when you traverse a linked list?

    1. Access Node A → 🔴 Cache Miss (CPU fetches from slow RAM)
    2. Go to Node D (stored far away) → 🔴 Cache Miss
    3. Go to Node B (stored elsewhere) → 🔴 Cache Miss

    Because the nodes aren’t next to each other, the 64-byte cache line the CPU loaded is useless. The CPU has to constantly go back to the RAM for every single step.

    The Takeaway

    Big-O tells you how an algorithm scales. Hardware tells you how fast it actually runs.

    For most real-world workloads — especially tight loops over collections — arrays (or array-backed structures like std::vector, slice in Go, ArrayList in Java) will outperform linked lists, even when textbook complexity says otherwise.

    Always remember: your code runs on a machine, not on a chalkboard. ⚡
